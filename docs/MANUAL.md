# Руководство оператора и администратора Bridge Local (MANUAL)

Данный документ представляет собой единое практическое руководство по установке, настройке, ежедневному использованию и диагностике платформы **Bridge Local** на операционных системах Linux и Windows.

---

## 1. Обзор платформы и назначение

**Bridge Local** — это легковесный высокопроизводительный P2P мост прямого межмашинного взаимодействия между рабочими станциями Linux и Windows по локальной вычислительной сети (LAN).

Платформа решает комплекс задач совместной работы двух сред:
- **Общее файловое хранилище («Карман» / Pocket Storage):** Надежная передача и синхронизация файлов любого объема блоками по 64 КБ с проверкой целостности SHA-256 и атомарным переименованием. Не требует настройки Samba, SMB, NFS или облачных сервисов.
- **Мгновенный обмен заметками и ссылками (Notes Engine):** Оперативная пересылка текстовых сообщений, ссылок и кодовых сниппетов между экранами рабочих станций с фиксацией в структурированном журнале.
- **Удаленное выполнение команд PowerShell (Remote Execution):** Запуск административных и рабочих скриптов на Windows-машине непосредственно из консоли Linux с гарантированным декодированием вывода в UTF-8 (`chcp 65001`), контролем таймаутов и автоматическим каскадным уничтожением зависших процессов.
- **Двойной интерфейс управления:**
  - **Для человека:** Полноэкранный интерактивный терминальный интерфейс (TUI) с промышленной палитрой Titanium Vivid, переключением 8 вкладок, скроллингом списков и немерцающей анимацией процессов.
  - **Для ИИ-агентов (Antigravity agy_cli):** Строгий режим `--json` с машиночитаемыми схемами ответов, детерминированными кодами возврата (0..5), нулевым ANSI-мусором и отсутствием блокировок ввода.

## 2. Системные требования и сетевые порты

- **Сетевой транспорт:** TCP-сокет, порт по умолчанию: `9732` (настраивается в диапазоне `1024..65535`).
- **Требования Windows:** Windows 10, Windows 11 или Windows Server 2019/2022/2025 (x64). Для фоновой работы службы требуются права локального Администратора.
- **Требования Linux:** Дистрибутив Linux x86_64 с версией ядра 5.x/6.x.
- **Среда выполнения Python:**
  - При использовании готовых автономных пакетов (`BridgeLocal-Windows-x64.zip` и `BridgeLocal-Linux-x64.zip`) наличие установленного Python на целевых машинах **не требуется**.
  - При сборке или запуске из исходного кода: Python 3.12 - 3.14, пакетный менеджер `uv` или `pip`.

## 3. Развертывание на стороне Windows (Серверный агент)

На машине Windows функционирует серверный агент `bridge-agent` (`BridgeLocalAgent`), принимающий входящие TCP-соединения от клиента Linux.

### Вариант 3.1. Запуск из автономного релизного пакета (Рекомендуется)

1. Скачайте и распакуйте архив `BridgeLocal-Windows-x64.zip` в постоянный рабочий каталог (например, `C:\BridgeLocal`).
2. Содержимое распакованного каталога:
   - `bridge-agent.exe` — скомпилированный автономный исполняемый файл агента.
   - `setup_connection.bat` — интерактивный мастер первоначальной настройки.
   - `run_agent.bat` — скрипт консольного запуска для тестирования и отладки.
   - `install_service.bat` — установка системной службы Windows SCM.
   - `uninstall_service.bat` — остановка и полное удаление службы.
   - `bridge.toml` — файл конфигурации параметров агента.
   - `pocket\` — каталог общего хранилища файлов.

#### Шаг 1: Интерактивная настройка параметров (`setup_connection.bat`)
Запустите файл `setup_connection.bat` двойным кликом мыши:
- Скрипт просканирует доступные сетевые адаптеры и отобразит список активных локальных IPv4-адресов (например, `192.168.1.150`).
- Подтвердите или введите порт прослушивания (по умолчанию: `9732`).
- Задайте ключ безопасности PSK (Pre-Shared Key) либо нажмите Enter для использования автоматически сгенерированного токена.
- Мастер запишет параметры в `bridge.toml` и отобразит готовую строку для подключения с Linux.

#### Шаг 2: Выбор режима работы

- **Режим отладки в окне консоли:**
  Запустите `run_agent.bat`. В открывшемся окне отобразится статус привязки к порту `0.0.0.0:9732` и трассировка входящих сетевых пакетов. Этот режим удобен для первичной проверки связи. Остановка производится нажатием комбинации клавиш `Ctrl+C`.

- **Режим постоянной системной службы (Production SCM Service):**
  Для работы агента в фоновом режиме (включая работу до входа пользователя в систему):
  1. Кликните правой кнопкой мыши по `install_service.bat` и выберите **«Запуск от имени администратора»**.
  2. Скрипт автоматически выполнит следующие операции:
     - Зарегистрирует системную службу `BridgeLocalAgent` в Service Control Manager (SCM).
     - Установит политику автоматического перезапуска службы при сбоях (через 5, 10 и 30 секунд).
     - Создаст разрешающее правило для входящего TCP-трафика на порту 9732 в Брандмауэре Windows.
     - Добавит каталог установки в исключения антивируса Windows Defender.
     - Отключит службу индексирования Windows Search для каталога `pocket` во избежание конфликтов блокировки файлов.
     - Интегрирует пункт «Отправить в Карман (Bridge Local)» в контекстное меню Проводника Windows.
     - Запустит службу в фоновом режиме.

#### Проверка состояния службы Windows:
В терминале PowerShell:
```powershell
Get-Service -Name BridgeLocalAgent
```

#### Удаление службы:
Для полной деинсталляции службы, удаления правил брандмауэра и очистки реестра запустите `uninstall_service.bat` от имени Администратора.

## 4. Развертывание на стороне Linux (Клиент оператора)

На машине Linux используется клиентская консольная утилита `bridge-cli`.

### Вариант 4.1. Установка из автономного пакета

1. Скачайте и распакуйте архив `BridgeLocal-Linux-x64.zip`:
   ```bash
   unzip BridgeLocal-Linux-x64.zip -d ~/BridgeLocal
   cd ~/BridgeLocal
   chmod +x bridge-cli
   ```
2. Для удобства вызова из любой директории создайте симлинк:
   ```bash
   sudo ln -s ~/BridgeLocal/bridge-cli /usr/local/bin/bridge-cli
   ```

### Вариант 4.2. Установка из исходного кода через uv

```bash
# Клонирование и установка через uv tool (изолированное окружение)
git clone https://github.com/Anhelm01/Bridge_Local.git
cd Bridge_Local
uv tool install .
```

### Шаг 1: Подключение к Windows-агенту

Для подключения достаточно выполнить одну команду с указанием IP-адреса и порта Windows-машины:
```bash
bridge-cli connect 192.168.1.150:9732
```
Если используется токен аутентификации PSK:
```bash
bridge-cli connect 192.168.1.150:9732 --token "ВашСекретныйТокен"
```
Команда выполнит проверку сокета в реальном времени и атомарно сохранит параметры в конфигурационный файл `bridge.toml`.

Альтернативно можно воспользоваться пошаговым интерактивным мастером:
```bash
bridge-cli setup
```

bridge-cli ping

### Фоновая синхронизация каталога кармана (systemd unit)

Для непрерывной фоновой синхронизации файлов между Linux и Windows можно включить пользовательский сервис systemd:
```bash
mkdir -p ~/.config/systemd/user
cp scripts/systemd/bridge-client-sync.service ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now bridge-client-sync.service
```

Проверка состояния сервиса:
```bash
systemctl --user status bridge-client-sync.service
```

## 5. Использование терминального интерфейса TUI

Терминальный пользовательский интерфейс (TUI) запускается командой:
```bash
bridge-cli tui
```
*(При запуске `bridge-cli` без аргументов в интерактивном TTY терминале TUI запускается автоматически).*

Интерфейс спроектирован на базе библиотеки Rich с использованием палитры **Titanium Vivid / Cyber-Industrial**, безопасного буфера альтернативного экрана (`alternate screen buffer`) и предотвращения мерцания при обновлении кадров.

### Структура функциональных экранов (8 вкладок)

1. **1 / SPLASH (Экран приветствия):**
   Фирменный экран BRIDGES Master с неофетч-сводкой параметров системы: сетевой статус, IP-адреса локального и удаленного узлов, объем кармана, режим аутентификации.
2. **2 / DASH (Оперативный дашборд):**
   Сводная панель текущего состояния: статус связи и пинг, загрузка CPU и оперативной памяти Windows-агента, счетчики файлов в кармане, индикатор новых заметок и командная строка быстрого действия (`send <file>`, `exec <cmd>`, `refresh`).
3. **3 / POCKET (Хранилище кармана):**
   Таблица локальных файлов кармана с размерами, направлением передачи и превью хэшей SHA-256. В нижней части расположена строка прямой отправки файлов (`PUSH FILE >`).
4. **4 / NOTES (Журнал заметок):**
   Лента текстовых сообщений и ссылок с отметками времени, автором и статусом доставки. В нижней части — строка ввода новой заметки (`NOTE >`).
5. **5 / EXEC (Удаленный терминал PowerShell):**
   Интерактивная консоль удаленного выполнения команд на Windows. Отображает журнал ранее выполненных команд, потоки stdout/stderr и коды завершения.
6. **6 / CONFIG (Реестр узлов и параметров):**
   Таблица зарегистрированных узлов сети, сетевых адресов, параметров heartbeat и статуса криптографической аутентификации HMAC-SHA256.
7. **7 / DEV (Диагностика и системные логи):**
   Технический экран детальной диагностики: параметры сокетов, тайминги fail-fast, абсолютные пути к файлам конфигурации, кармана и логов.
8. **8 / CONNECT (Быстрое переключение целевого узла):**
   Экран оперативного изменения адреса удаленного узла (IP, порт, токен) без выхода из TUI и без ручной правки TOML-файлов.

### Клавиши управления TUI

| Клавиши | Функция |
|:---|:---|
| **`Стрелка Влево` (`←`) / `Вправо` (`→`)** | Мгновенное переключение на предыдущую / следующую вкладку (удобно на любой клавиатуре без Fn). |
| **`Цифры 1..8`** | Прямой переход на вкладку 1..8 в режимах просмотра (SPLASH, DASH, CONFIG, DEV) или через `Alt+1`..`Alt+8`. |
| **`Tab` / `Shift+Tab`** | Последовательное циклическое переключение вперед / назад между всеми 8 вкладками. |
| **`[` / `]`** | Переход на предыдущую / следующую вкладку в режимах просмотра. |
| **`F1` .. `F8`** | Прямой переход к соответствующей вкладке (сохранено как совместимый fallback). |
| **`Стрелка Вверх` (`↑`) / `Вниз` (`↓`)** | Построчный вертикальный скроллинг списков файлов в POCKET, заметок в NOTES, вывода в EXEC и журнала в DEV. |
| **`Page Up` / `Page Down`** | Постраничный скроллинг списков файлов, заметок и логов на экран вверх/вниз. |
| **`Home` / `End`** | Быстрый переход в начало / в конец списка. |
| **`Enter`** | Подтверждение и отправка введенного текста (команды, пути файла или заметки). |
| **`Escape`** | Очистка текущего буфера ввода; при пустом буфере — переход на экран DASH. |
| **`Ctrl+C` / `Ctrl+Q`** | Выход из TUI с корректным восстановлением настроек и буфера терминала. |
| **Команды двоеточия** | Ввод `:1`..`:8` или `:dash`, `:pocket`, `:notes`, `:exec`, `:q` в любой строке ввода. |

## 6. Повседневные сценарии работы через CLI

### 6.1. Прямая отправка файлов (Direct File Drop)
```bash
# Отправка одного файла в удаленный карман
bridge-cli send archive.zip

# Отправка нескольких файлов с помещением в подкаталог
bridge-cli send doc1.pdf doc2.pdf image.png --target-dir "reports"
```

### 6.2. Синхронизация файлов общего хранилища (Pocket)
```bash
# Просмотр статуса синхронизации и очереди передачи
bridge-cli pocket status

# Полная двунаправленная синхронизация
bridge-cli pocket sync

# Однонаправленная выгрузка на Windows
bridge-cli pocket sync --direction push

# Однонаправленное скачивание с Windows
bridge-cli pocket sync --direction pull

# Скачивание конкретного удаленного файла
bridge-cli pocket pull "reports/doc1.pdf" --dest ./local_doc.pdf
```

### 6.3. Удаленный запуск PowerShell на Windows
```bash
# Простой опрос запущенных служб
bridge-cli exec "Get-Service -Name BridgeLocalAgent"

# Выполнение команды с ограничением времени 15 секунд
bridge-cli exec "Get-ChildItem -Path C:\ -Recurse" --timeout 15

# Запуск команды без повышенных привилегий
bridge-cli exec "whoami" --no-admin
```

### 6.4. Быстрый обмен заметками и ссылками
```bash
# Отправка ссылки или текста на Windows
bridge-cli note send "https://github.com/Anhelm01/Bridge_Local"

# Просмотр последних 10 заметок
bridge-cli note list --limit 10

# Просмотр только новых непрочитанных заметок
bridge-cli note list --unread

# Отметка заметки как прочитанной
bridge-cli note read "e9a03bc2-44df-4416-8f3a-cb28646b1a11"
```

## 7. Протокол взаимодействия для ИИ-агентов (agy_cli)

При интеграции с агентами искусственного интеллекта (`agy_cli`, Antigravity CLI) каждая команда `bridge-cli` вызывается с флагом `--json` (или `-j`):

```bash
bridge-cli exec "Get-Process" --json
```

**Гарантии режима `--json`:**
1. Вывод в `stdout` представляет собой строго валидный JSON-документ без ANSI-цветов, рамок и псевдографики.
2. Процесс никогда не ожидает ввода из `stdin` и не блокирует пайплайны автоматизации.
3. Коды возврата процесса строго стандартизированы (`bridge_client_linux.exit_codes.ExitCode`):

| Код выхода | Символическое имя | Причина |
|:---:|:---|:---|
| **`0`** | `SUCCESS` | Команда или операция успешно выполнена. |
| **`1`** | `GENERAL_ERROR` | Неверный синтаксис аргументов, ошибка в конфигурации или внутренний сбой. |
| **`2`** | `NETWORK_ERROR` | Целевой узел недоступен, соединение отклонено или сброшено сетью. |
| **`3`** | `AUTH_ERROR` | Неверный ключ PSK, ошибка проверки подписи HMAC или атака повторного воспроизведения (Replay). |
| **`4`** | `COMMAND_FAILED` | Процесс PowerShell на Windows завершился с ненулевым кодом выхода. |
| **`5`** | `TIMEOUT` | Превышен лимит времени выполнения команды PowerShell или ожидания сетевого ответа. |

## 8. Диагностика и устранение неполадок

### 8.1. Сетевая ошибка (Код 2 / Network Error / Connection Refused)
1. **Проверьте запуск агента на Windows:**
   В PowerShell на Windows выполните `Get-Service BridgeLocalAgent`. Если служба остановлена, запустите: `Start-Service BridgeLocalAgent`.
2. **Проверьте правила Брандмауэра Windows:**
   Убедитесь, что порт 9732 открыт для входящих TCP-соединений. При необходимости добавьте правило:
   ```powershell
   New-NetFirewallRule -DisplayName "Bridge Local" -Direction Inbound -LocalPort 9732 -Protocol TCP -Action Allow
   ```
3. **Изоляция клиентов Wi-Fi (Client Isolation):**
   Если обе машины подключены к Wi-Fi роутеру, проверьте, не включена ли функция изоляции клиентов (AP Isolation). Проверьте доступность узла стандартным ICMP-пингом: `ping 192.168.1.150`.

### 8.2. Ошибка аутентификации (Код 3 / Auth Error)
1. **Несовпадение токена PSK:**
   Значение параметра `psk_token` в файле `bridge.toml` на машине Linux должно посимвольно совпадать со значением `psk_token` на машине Windows.
2. **Рассинхронизация системных часов (Clock Skew):**
   Для защиты от Replay-атак пакеты отклоняются, если расхождение часов между узлами превышает 60 секунд. Настройте синхронизацию времени по протоколу NTP на обеих машинах.

### 8.3. Зависание процессов и таймауты (Код 5 / Timeout)
При выполнении длительных скриптов увеличьте параметр таймаута с помощью ключа `--timeout <секунды>`:
```bash
bridge-cli exec "Start-Sleep -Seconds 45; dir C:\\" --timeout 60
```
Если команда превышает установленный лимит, подсистема `process_killer` на стороне агента автоматически находит идентификатор процесса и принудительно завершает все его дочерние процессы (`taskkill /F /T /PID`), исключая утечку памяти и появление зомби-процессов.

### 8.4. Расположение журналов аудита
- **Windows-агент:** Все входящие сетевые сессии, выполненные команды и файловые операции записываются в ежедневный журнал формата JSONL:
  `C:\BridgeLocal\pocket\logs\YYYY-MM-DD.jsonl`
- **Linux-клиент:** При включенном `dev_mode = true` в `bridge.toml` подробная микросекундная трассировка сетевых пакетов выводится в консоль либо в файл, указанный в параметре `logging.file_output`.
