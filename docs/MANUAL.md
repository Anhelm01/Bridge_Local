# Руководство оператора и администратора Bridge Local (MANUAL)

Данный документ представляет собой единое практическое руководство по установке, настройке, компиляции, ежедневному использованию и диагностике платформы **Bridge Local** на операционных системах Linux и Windows.

Руководство охватывает два основных сценария эксплуатации:
1. **Работа из ветки Master (Git clone / Исходный код):** Прямой запуск из репозитория, автоматическое подключение зависимостей через папки, самостоятельная локальная компиляция `bridge-agent.exe`, настройка контекстного меню Проводника и служб через готовые bat-скрипты.
2. **Работа из готового релизного дистрибутива (Standalone ZIP):** Запуск скомпилированных бинарных файлов без необходимости установки Python на целевых машинах.

---

## 1. Обзор платформы и назначение

**Bridge Local** — это легковесный высокопроизводительный P2P мост прямого межмашинного взаимодействия между рабочими станциями Linux и Windows по локальной вычислительной сети (LAN).

Платформа объединяет ключевые функции для бесшовной совместной работы двух сред:
- **Общее файловое хранилище («Карман» / Pocket Storage):** Надежная передача и синхронизация файлов любого объема блоками по 64 КБ с проверкой целостности SHA-256 и атомарным переименованием. Не требует настройки Samba, SMB, NFS или облачных сервисов.
- **Интеграция с Проводником Windows (Контекстное меню):** Отправка любого файла или папки в Карман прямо из Проводника Windows по правому клику мыши («Отправить в Карман (Bridge Local)») со всплывающим системным подтверждением.
- **Мгновенный обмен заметками и ссылками (Notes Engine):** Оперативная пересылка текстовых сообщений, ссылок и кодовых сниппетов между экранами рабочих станций с фиксацией в структурированном журнале.
- **Удаленное выполнение команд PowerShell (Remote Execution):** Запуск административных и рабочих скриптов на Windows-машине непосредственно из консоли Linux с гарантированным декодированием вывода в UTF-8 (`chcp 65001`), контролем таймаутов и автоматическим каскадным уничтожением зависших процессов.
- **Двойной интерфейс управления:**
  - **Для человека:** Полноэкранный интерактивный терминальный интерфейс (TUI) с промышленной палитрой Titanium Vivid, переключением 8 вкладок через стрелки `<-` / `->`, клавиши `1..8` и `Tab`, скроллингом списков `Arrow Up/Down`, `Page Up/Down` и немерцающей анимацией процессов.
  - **Для ИИ-агентов (Antigravity agy_cli):** Строгий режим `--json` с машиночитаемыми схемами ответов, детерминированными кодами возврата (0..5), нулевым ANSI-мусором и отсутствием блокировок ввода.

## 2. Системные требования и сетевые порты

- **Сетевой транспорт:** TCP-сокет, порт по умолчанию: `9732` (настраивается в диапазоне `1024..65535`).
- **Требования Windows:** Windows 10, Windows 11 или Windows Server 2019/2022/2025 (x64). Для установки службы SCM требуются права локального Администратора. Для работы контекстного меню права администратора не требуются (установка в реестр HKCU).
- **Требования Linux:** Дистрибутив Linux x86_64 с версией ядра 5.x/6.x.
- **Среда выполнения Python:**
  - При сборке или запуске из ветки Master: Python 3.12 - 3.14.
  - При использовании автономных бинарников (`dist/bridge-cli` и `dist/bridge-agent.exe`): наличие установленного Python **не требуется**.

## 3. Запуск и эксплуатация мастер-версии на Windows (Git Master / Исходный код)

Этот раздел предназначен для работы с клонированным репозиторием Bridge Local на Windows-машине.

### 3.1. Структура каталогов и автоматическое чтение зависимостей

В репозитории исходный код разделен на модульные пакеты в подкаталоге `src/`:
```text
Bridge_Local/
|-- bridge.toml                  # Конфигурационный файл моста
|-- pyproject.toml               # Метаданные и зависимости проекта
|-- setup_connection.bat         # Мастер настройки IP, порта и токена
|-- run_agent.bat                # Запуск агента в консоли
|-- build_windows_exe.bat        # Локальная компиляция bridge-agent.exe
|-- install_context_menu.bat     # Регистрация пункта в Проводнике Windows
|-- uninstall_context_menu.bat   # Удаление пункта из Проводника
|-- drop_to_pocket.bat           # Обработчик отправки файлов в Карман
|-- install_service.bat          # Регистрация службы Windows SCM (Администратор)
|-- uninstall_service.bat        # Удаление службы SCM (Администратор)
|-- pocket/                      # Папка локального кармана
|-- src/
|   |-- bridge_core/             # Ядро: протокол 'BR', транспорт, pocket, notes, security
|   |-- bridge_agent_win/        # Агент Windows: служба, PowerShell executor, контекстное меню
|   |-- bridge_client_linux/     # Клиент Linux: CLI, TUI, exit codes
|   `-- bridge_local/            # Универсальная точка входа
`-- scripts/
    |-- build-windows-agent.ps1  # PowerShell-скрипт сборки PyInstaller
    `-- windows/                 # Резервные копии bat-скриптов
```

#### Как решена проблема импорта зависимостей через папки:
1. **Все bat-скрипты в корне репозитория** перед запуском автоматически определяют корень репозитория (`%~dp0`) и устанавливают переменную окружения `set PYTHONPATH=%~dp0src;%PYTHONPATH%`. Благодаря этому Python мгновенно видит все пакеты `bridge_core`, `bridge_agent_win` и `bridge_local` без ошибок `ModuleNotFoundError`.
2. **Все точки входа Python** (`__main__.py`, `cli.py`, `context_menu.py`) содержат встроенную динамическую интроспекцию `sys.path`. Даже если вы запустите скрипт напрямую из любой случайной директории (`python src/bridge_agent_win/cli.py`), путь к каталогу `src/` будет добавлен автоматически.
3. **Автоматическое обнаружение окружения:** Батники в первую очередь ищут локальное виртуальное окружение `.venv\Scripts\python.exe`, затем скомпилированный `dist\bridge-agent.exe`, а при их отсутствии используют системный `python`.

### 3.2. Первоначальная установка зависимостей на Windows

Откройте терминал PowerShell или командную строку CMD в корне репозитория:

```powershell
# Вариант А: Использование стандартного Python venv
python -m venv .venv
.\.venv\Scripts\activate
pip install --upgrade pip
pip install -e ".[windows,dev]"

# Вариант Б: Использование менеджера uv (если установлен)
uv sync --extra windows --extra dev
```

### 3.3. Шаг 1: Интерактивная настройка параметров (`setup_connection.bat`)

Запустите файл `setup_connection.bat` двойным кликом мыши:
1. Скрипт просканирует локальные сетевые интерфейсы и выведет активные IP-адреса Windows (например, `192.168.1.150`).
2. Предложит подтвердить TCP-порт (по умолчанию: `9732`).
3. Предложит задать ключ безопасности PSK (Pre-Shared Key) либо нажать Enter для сохранения надежного ключа по умолчанию.
4. Параметры будут сохранены в `bridge.toml`. Скрипт выведет готовую строку для подключения с Linux:
   ```text
   bridge-cli connect 192.168.1.150:9732
   ```

### 3.4. Шаг 2: Консольный запуск агента (`run_agent.bat`)

Для первого тестирования и отладки запустите `run_agent.bat`:
- Откроется окно консоли, где агент начнет слушать входящие соединения на `0.0.0.0:9732`.
- В окно выводится детальная трассировка каждого входящего пакета, пинга и файловой операции.
- Остановка агента производится нажатием комбинации клавиш `Ctrl+C`.

### 3.5. Шаг 3: Самостоятельная компиляция `bridge-agent.exe` (`build_windows_exe.bat`)

Если вы хотите получить автономный скомпилированный бинарник без зависимостей прямо на своей машине:
1. Запустите `build_windows_exe.bat` двойным кликом мыши (или в PowerShell: `.\scripts\build-windows-agent.ps1`).
2. Скрипт выполнит:
   - Проверку наличия PyInstaller и системных компонентов `pywin32`.
   - Автоматическую регистрацию системных библиотек `pywin32_postinstall.py`.
   - Сборку исполняемого файла по спецификации `bridge-agent.spec` с упаковкой всех модулей ядра, исполнителя PowerShell и службы SCM.
   - Проверку целостности собранного бинарника и расчет контрольной суммы SHA-256.
3. Готовый файл появится по пути: `dist\bridge-agent.exe`.
4. После этого все bat-скрипты (`run_agent.bat`, `setup_connection.bat`, `install_service.bat`) автоматически переключатся на запуск скомпилированного `dist\bridge-agent.exe`.

### 3.6. Шаг 4: Установка контекстного меню Проводника (`install_context_menu.bat`)

Для быстрой отправки файлов в Карман прямо из Проводника Windows:
1. Запустите `install_context_menu.bat` двойным кликом мыши.
2. Скрипт зарегистрирует пункт **«Отправить в Карман (Bridge Local)»** в реестре Windows текущего пользователя (`HKEY_CURRENT_USER`). Права администратора не требуются.
3. **Как это работает при правом клике на файл или папку:**
   - Вы кликаете правой кнопкой мыши по любому файлу (например, на Рабочем столе или в Загрузках) и выбираете «Отправить в Карман (Bridge Local)».
   - Вызывается надежный обработчик `drop_to_pocket.bat`, который переходит в каталог Bridge Local, находит конфигурацию `bridge.toml` и атомарно копирует файл в локальный каталог `pocket\`.
   - На экране Windows появляется системное окно-уведомление с подтверждением успешной отправки и полным путем назначения.
   - Если файл заблокирован другой программой, на экране появится понятное сообщение об ошибке с кодом сбоя.
4. **Удаление пункта меню:** Запустите `uninstall_context_menu.bat`.

### 3.7. Шаг 5: Установка постоянной фоновой службы Windows SCM (`install_service.bat`)

Для того чтобы агент работал в фоне как системная служба (включая работу до входа пользователя в систему):
1. Кликните правой кнопкой мыши по `install_service.bat` и выберите **«Запуск от имени администратора»**.
2. Скрипт автоматически выполнит:
   - Регистрацию системной службы `BridgeLocalAgent` в Service Control Manager (SCM).
   - Настройку политики автоматического перезапуска службы при сбоях (через 5, 10 и 30 секунд).
   - Создание разрешающего правила для порта 9732 в Брандмауэре Windows.
   - Добавление папки установки в исключения Windows Defender.
   - Отключение индексации Windows Search для каталога `pocket` во избежание файловых блокировок.
   - Установку контекстного меню Проводника.
   - Запуск службы в фоновом режиме.
3. Проверка службы в PowerShell:
   ```powershell
   Get-Service -Name BridgeLocalAgent
   ```
4. **Удаление службы:** Запустите `uninstall_service.bat` от имени Администратора.

## 4. Развертывание из автономного дистрибутива (Standalone ZIP)

Если на машине Windows нет Python и не планируется работа с исходным кодом:
1. Скачайте архив `BridgeLocal-Windows-x64.zip` (со страницы GitHub Releases либо собранный на машине разработчика).
2. Распакуйте архив в постоянный каталог (например, `C:\BridgeLocal`).
3. Внутри распакованного каталога уже содержатся:
   - `bridge-agent.exe` — готовый исполняемый файл агента.
   - `setup_connection.bat`, `run_agent.bat`, `install_service.bat`, `uninstall_service.bat`.
   - `install_context_menu.bat`, `uninstall_context_menu.bat`, `drop_to_pocket.bat`.
   - `bridge.toml` и каталог `pocket\`.
4. Запустите `setup_connection.bat` для настройки IP/порта, затем `install_service.bat` от имени Администратора для постоянной фоновой работы.

## 5. Развертывание и работа со стороны Linux (Клиент оператора)

На машине Linux работает клиентская утилита `bridge-cli` и терминальный интерфейс TUI.

### 5.1. Установка на Linux

#### Вариант А: Использование скомпилированного бинарника `bridge-cli`
1. Скачайте и распакуйте архив `BridgeLocal-Linux-x64.zip`:
   ```bash
   unzip BridgeLocal-Linux-x64.zip -d ~/BridgeLocal
   cd ~/BridgeLocal
   chmod +x bridge-cli
   sudo ln -s ~/BridgeLocal/bridge-cli /usr/local/bin/bridge-cli
   ```

#### Вариант Б: Запуск из репозитория (Git Master)
```bash
git clone https://github.com/Anhelm01/Bridge_Local.git
cd Bridge_Local
uv sync --extra linux --extra dev
# Запуск через uv
uv run bridge-cli --help
```

### 5.2. Подключение к Windows-агенту

Для подключения достаточно одной команды с указанием IP-адреса и порта Windows:
```bash
bridge-cli connect 192.168.1.150:9732
```
Если на Windows был задан собственный ключ PSK:
```bash
bridge-cli connect 192.168.1.150:9732 --token "ВашСекретныйТокен"
```
Команда проверит сокет в реальном времени и атомарно сохранит параметры в `bridge.toml`.

Проверка доступности узла:
```bash
bridge-cli ping --count 4
bridge-cli status
```

### 5.3. Терминальный интерфейс TUI

Запуск полноэкранного интерфейса:
```bash
bridge-cli tui
```
*(При запуске `bridge-cli` без параметров в интерактивном терминале TUI открывается автоматически).*

#### Структура функциональных экранов (8 вкладок)
1. **1 / SPLASH (Экран приветствия):** Сводка системы BRIDGES Master, статус сети, адреса узлов, объем кармана, статус PSK.
2. **2 / DASH (Оперативный дашборд):** Статус связи и RTT пинга, загрузка CPU и RAM Windows-агента, очереди кармана, быстрые команды (`send <file>`, `exec <cmd>`, `refresh`).
3. **3 / POCKET (Хранилище кармана):** Таблица файлов кармана, размеры, направления синхронизации, хэши SHA-256. Внизу — строка прямой отправки файлов (`PUSH FILE >`).
4. **4 / NOTES (Журнал заметок):** Лента сообщений и ссылок с отметками времени, автором и статусом доставки. Внизу — строка ввода новой заметки (`NOTE >`).
5. **5 / EXEC (Удаленный терминал PowerShell):** Интерактивная консоль выполнения команд на Windows. Журнал вызовов, потоки stdout/stderr и коды завершения.
6. **6 / CONFIG (Реестр узлов и параметров):** Настройки таймингов, сокетов, heartbeat и ключей безопасности.
7. **7 / DEV (Диагностика и системные логи):** Детальная техническая диагностика сокетов, таймингов fail-fast, путей к файлам и логам.
8. **8 / CONNECT (Быстрое переключение узла):** Оперативное изменение IP, порта и токена без выхода из TUI.

#### Клавиши управления TUI

| Клавиши | Функция |
|:---|:---|
| **`Стрелка Влево` (`<-`) / `Вправо` (`->`)** | Переключение на предыдущую / следующую вкладку (удобно на любой клавиатуре без Fn). |
| **`Цифры 1..8`** | Прямой переход на вкладку 1..8 в экранах просмотра (SPLASH, DASH, CONFIG, DEV) или через `Alt+1`..`Alt+8` из любого экрана. |
| **`Tab` / `Shift+Tab`** | Последовательное циклическое переключение вперед / назад между всеми 8 вкладками. |
| **`[` / `]`** | Переход на предыдущую / следующую вкладку в режимах просмотра. |
| **`F1` .. `F8`** | Прямой переход к соответствующей вкладке (сохранено для совместимости). |
| **`Стрелка Вверх` (`^`) / `Вниз` (`v`)** | Построчный вертикальный скроллинг списков файлов в POCKET, заметок в NOTES, вывода в EXEC и журнала в DEV. |
| **`Page Up` / `Page Down`** | Постраничный скроллинг списков файлов, заметок и логов на экран вверх/вниз. |
| **`Home` / `End`** | Быстрый переход в начало / в конец списка. |
| **`Enter`** | Подтверждение и отправка введенного текста (команды, пути файла или заметки). |
| **`Escape`** | Очистка текущего буфера ввода; при пустом буфере — переход на экран DASH. |
| **`Ctrl+C` / `Ctrl+Q`** | Выход из TUI с корректным восстановлением настроек терминала. |
| **Буквенные клавиши** | Полностью изолированы от навигации: вы можете свободно печатать любые команды и пути в буфер ввода без риска случайного переключения экранов. |

## 6. Повседневные сценарии работы и синхронизация Кармана

### 6.1. Двусторонняя синхронизация файлов через Карман
1. **Отправка с Windows на Linux:**
   - На Windows кликните правой кнопкой мыши по файлу -> **«Отправить в Карман (Bridge Local)»**.
   - Файл скопируется в локальный карман Windows.
   - На Linux выполните:
     ```bash
     bridge-cli pocket sync
     ```
     или откройте вкладку `[3:POCKET]` в TUI. Файл автоматически загрузится в локальный карман на Linux.
2. **Отправка с Linux на Windows:**
   - Выполните команду прямой отправки:
     ```bash
     bridge-cli send report.pdf
     ```
     Файл блоками по 64 КБ с проверкой SHA-256 передастся по TCP-сокету и появится в кармане на Windows.

### 6.2. Фоновая синхронизация на Linux через systemd
Для постоянной фоновой синхронизации файлов включите пользовательский сервис:
```bash
mkdir -p ~/.config/systemd/user
cp scripts/systemd/bridge-client-sync.service ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now bridge-client-sync.service
```

### 6.3. Удаленный запуск PowerShell
```bash
# Получение статуса службы Windows
bridge-cli exec "Get-Service -Name BridgeLocalAgent"

# Запуск скрипта с контролем таймаута
bridge-cli exec "Get-Process | Sort-Object CPU -Descending | Select-Object -First 10" --timeout 15
```

### 6.4. Обмен заметками и ссылками
```bash
# Отправка ссылки на Windows
bridge-cli note send "https://github.com/Anhelm01/Bridge_Local"

# Просмотр списка заметок
bridge-cli note list --limit 10
```

## 7. Протокол взаимодействия для ИИ-агентов (agy_cli)

При вызове из скриптов автоматизации или ИИ-агентов Antigravity CLI (`agy_cli`) используйте флаг `--json` (или `-j`):

```bash
bridge-cli exec "Get-Process" --json
```

**Стандартизированные коды завершения (`ExitCode`):**
- `0` (`SUCCESS`): Операция успешно завершена.
- `1` (`GENERAL_ERROR`): Ошибка аргументов, конфигурации или внутренний сбой.
- `2` (`NETWORK_ERROR`): Узел недоступен, соединение отклонено.
- `3` (`AUTH_ERROR`): Неверный ключ PSK или ошибка HMAC подписи.
- `4` (`COMMAND_FAILED`): Удаленный процесс PowerShell завершился с ненулевым кодом.
- `5` (`TIMEOUT`): Превышен лимит времени ожидания ответа или выполнения команды.

## 8. Диагностика и решение неполадок (Troubleshooting)

1. **Ошибка подключения (Код 2 / Connection Refused):**
   - Убедитесь, что агент на Windows запущен (`run_agent.bat` или служба `Get-Service BridgeLocalAgent`).
   - Проверьте Брандмауэр Windows: порт 9732 TCP должен быть разрешен. Для ручного открытия правила выполните в PowerShell от Администратора:
     ```powershell
     New-NetFirewallRule -DisplayName "Bridge Local" -Direction Inbound -LocalPort 9732 -Protocol TCP -Action Allow
     ```
   - Проверьте доступность узла стандартным пингом: `ping <IP_WINDOWS>`. Если пинг не проходит, проверьте, не включена ли на роутере изоляция клиентов (AP Isolation).

2. **Не работает контекстное меню Проводника:**
   - Запустите `install_context_menu.bat` в корне репозитория.
   - Скрипт автоматически создаст привязку к `drop_to_pocket.bat` с правильным `PYTHONPATH`.
   - Проверьте, что в корне репозитория присутствует файл `bridge.toml`. При отправке файла должно всплыть системное окно Windows с сообщением об успехе.

3. **Ошибка аутентификации (Код 3 / Auth Error):**
   - Убедитесь, что значение `psk_token` в файле `bridge.toml` на Linux и на Windows абсолютно одинаково.
   - Проверьте расхождение системных часов между машинами (не должно превышать 60 секунд для защиты от Replay-атак).

4. **Логирование и аудит:**
   - Все входящие подключения, выполненные команды PowerShell и файловые операции записываются в ежедневный журнал на Windows:
     `pocket\logs\YYYY-MM-DD.jsonl`
