# Руководство оператора Windows: Команды и глобальный запуск из любого каталога

Данный документ содержит пошаговое руководство по настройке серверного агента **Bridge Local (`bridge-agent`)** на операционной системе Windows для глобального запуска и выполнения команд из любого каталога файловой системы по умолчанию, а также полный справочник консольных команд и инструментов управления.

---

## 1. Архитектура конфигурации и поиск путей на Windows

При вызове `bridge-agent` из произвольной папки (например, `C:\Users\User\Downloads` или `C:\Windows\System32`), агент должен корректно загрузить сетевые параметры и привязаться к единому каталогу «Карман».

### 1.1. Алгоритм поиска конфигурационного файла

Ядро `bridge_core.config.BridgeConfig.load()` на платформе Windows ищет файл `bridge.toml` по цепочке приоритетов:

1. **Явный аргумент:** `--config "C:\путь\к\bridge.toml"`.
2. **Переменная окружения:** `BRIDGE_CONFIG` (системная или пользовательская переменная Windows).
3. **Текущий каталог:** `.\bridge.toml` (папка, где открыта консоль CMD или PowerShell).
4. **Каталог исполняемого файла:** папка, в которой лежит `bridge-agent.exe`.
5. **Родительский каталог бинарника:** `..\bridge.toml`.
6. **Фиксированный системный путь Windows:**
   `C:\BridgeLocal\bridge.toml`
7. **Временный каталог распаковки PyInstaller:** `_MEIPASS\bridge.toml`.

Если файл не найден, агент инициализируется со значениями по умолчанию (порт `9732`, адрес `0.0.0.0`).

### 1.2. Разрешение пути к каталогу «Карман» (`pocket.path`)

Параметр `path` в секции `[pocket]` определяет, куда помещаются входящие и исходящие файлы:
- **Относительный путь (`path = "./pocket"`):**
  Привязывается к расположению найденного `bridge.toml`. Если запустить агент без указания путей из случайной папки, может создаться нежелательная локальная папка `.\pocket`.
- **Абсолютный путь (рекомендуется):**
  Например:
  ```toml
  [pocket]
  path = "C:/BridgeLocal/pocket"
  ```
  Использование абсолютного пути гарантирует, что при вызове команд из любого места системы все файлы попадают в единое централизованное хранилище.

## 2. Пошаговая настройка глобального запуска по умолчанию

Чтобы агент `bridge-agent` и вспомогательные скрипты были доступны из любого окна терминала (CMD, PowerShell) без перехода в каталог репозитория, выполните следующие шаги.

### Шаг 1: Размещение дистрибутива в постоянном каталоге

Рекомендуется использовать стандартный путь `C:\BridgeLocal\` (или путь к вашей рабочей папке проекта, например `D:\progs\Bridge_Local-master`):

1. Создайте постоянный каталог:
   ```powershell
   New-Item -ItemType Directory -Path "C:\BridgeLocal" -Force
   New-Item -ItemType Directory -Path "C:\BridgeLocal\pocket" -Force
   ```
2. Поместите в `C:\BridgeLocal\` файлы дистрибутива:
   - `bridge-agent.exe` (скомпилированный бинарник)
   - `bridge.toml` (файл конфигурации)
   - `start.bat` и вспомогательные `.bat` скрипты

### Шаг 2: Добавление каталога в системную переменную PATH

Чтобы Windows находила команду `bridge-agent` из любой точки, добавьте каталог установки в системный `PATH`.

#### Через PowerShell (от имени Администратора):
```powershell
# Добавление в системную переменную PATH
$installDir = "C:\BridgeLocal"
$currentPath = [Environment]::GetEnvironmentVariable("Path", [EnvironmentVariableTarget]::Machine)

if ($currentPath -notlike "*$installDir*") {
    [Environment]::SetEnvironmentVariable("Path", "$currentPath;$installDir", [EnvironmentVariableTarget]::Machine)
    Write-Host "[OK] Каталог $installDir добавлен в системный PATH"
} else {
    Write-Host "[INFO] Каталог уже присутствует в PATH"
}
```

#### Через графический интерфейс Windows:
1. Нажмите `Win + R`, введите `sysdm.cpl` и нажмите Enter.
2. Перейдите на вкладку **«Дополнительно»** (Advanced) и нажмите кнопку **«Переменные среды...»** (Environment Variables).
3. В блоке «Системные переменные» выберите строку **Path** и нажмите **«Изменить...»**.
4. Нажмите **«Создать»** и введите путь: `C:\BridgeLocal`.
5. Нажмите **ОК** во всех окнах.

### Шаг 3: Фиксация центральной переменной конфигурации

Задайте системную переменную `BRIDGE_CONFIG`, чтобы агент гарантированно загружал единые параметры даже при вызове из сторонних процессов:

```powershell
[Environment]::SetEnvironmentVariable("BRIDGE_CONFIG", "C:\BridgeLocal\bridge.toml", [EnvironmentVariableTarget]::Machine)
```

Пример содержимого `C:\BridgeLocal\bridge.toml`:
```toml
[connection]
host = "0.0.0.0"          # Прослушивать все сетевые интерфейсы
port = 9732               # Порт для подключения с Linux
timeout_sec = 5.0
psk_token = "BridgeLocalSecretKey_Anhelm_2026_Secure"

[heartbeat]
interval_sec = 2.0
timeout_sec = 1.5
max_missed = 3
reconnect_delay_sec = 5.0

[pocket]
path = "C:/BridgeLocal/pocket"   # Абсолютный путь к единому карману
logs_subdir = "logs"
sync_watch = true
max_chunk_size = 65536
log_max_days = 30

[exec]
default_timeout_sec = 30.0
max_timeout_sec = 300.0
powershell_path = "powershell.exe"
encoding = "utf-8"
```

### Шаг 4: Открытие порта 9732 в Брандмауэре Windows

Для приема входящих RPC-подключений и синхронизации файлов с Linux необходимо разрешить входящий TCP-трафик на порту 9732.

Выполните в PowerShell от имени Администратора:
```powershell
netsh advfirewall firewall delete rule name="Bridge Local Daemon (TCP-In)" >$null 2>&1
netsh advfirewall firewall add rule name="Bridge Local Daemon (TCP-In)" dir=in action=allow protocol=TCP localport=9732 profile=any
Set-NetConnectionProfile -InterfaceAlias 'Ethernet' -NetworkCategory Private -ErrorAction SilentlyContinue
Write-Host "[OK] Порт 9732 разрешен для всех сетевых профилей"
```

### Шаг 5: Регистрация системной службы Windows (SCM)

Для работы агента по умолчанию в фоновом режиме (без открытых окон консоли и с автозапуском при включении ПК):

1. Откройте PowerShell от имени Администратора.
2. Выполните установку и запуск службы:
   ```powershell
   bridge-agent service install
   bridge-agent service start
   ```
3. Проверьте статус службы:
   ```powershell
   Get-Service -Name "BridgeLocalAgent"
   ```
   Служба перейдет в статус `Running` и будет автоматически стартовать при загрузке операционной системы.

### Шаг 6: Интеграция с контекстным меню Проводника (Explorer)

Чтобы отправлять любые файлы в карман кликом правой кнопки мыши:
```powershell
bridge-agent install-context-menu
```
После выполнения в контекстном меню всех файлов и папок Windows появится пункт:
**«Отправить в Карман (Bridge Local)»**.

### Шаг 7: Автозапуск системного трея (System Tray)

Для постоянной индикации состояния агента и быстрого доступа к карману из области уведомлений Windows:
1. Нажмите `Win + R`, введите `shell:startup` и нажмите Enter (откроется папка автозагрузки).
2. Создайте ярлык для файла `run_tray.bat` или команды `bridge-agent tray`.

### Шаг 8: Проверка вызова из произвольного каталога

Откройте новое окно терминала, перейдите в произвольную директорию и проверьте команды:
```cmd
cd C:\Windows\Temp

:: Проверка распознавания команды и пути конфига
bridge-agent config show

:: Проверка отправки тестового файла в карман
echo Привет из любой папки > test.txt
bridge-agent drop test.txt
```
Файл `test.txt` должен успешно скопироваться в `C:\BridgeLocal\pocket\`.

## 3. Справочник команд Windows (`bridge-agent`)

Утилита управления агентом `bridge-agent` поддерживает прямое консольное взаимодействие.

### 3.1. Быстрая настройка (`bridge-agent setup`)
Интерактивный пошаговый мастер для первоначальной конфигурации сети без ручного редактирования TOML:
```cmd
bridge-agent setup
```
Мастер определит доступные локальные сетевые интерфейсы, запросит порт, токен безопасности и путь к карману, после чего сохранит изменения.

---

### 3.2. Просмотр и изменение конфигурации (`bridge-agent config`)

#### Просмотр текущих настроек и доступных IP-адресов:
```cmd
bridge-agent config show
```
Выводит активный путь к `bridge.toml`, bind-адрес, порт, статус токена и список IP-адресов, которые необходимо указывать на машине Linux для подключения.

#### Изменение параметров «на лету»:
```cmd
:: Смена порта
bridge-agent config --port 9732

:: Смена адреса прослушивания
bridge-agent config --host 0.0.0.0

:: Обновление токена безопасности PSK
bridge-agent config --token "MySecureToken2026"

:: Смена пути к карману
bridge-agent config --pocket "C:\BridgeLocal\pocket"
```

---

### 3.3. Управление фоновой службой Windows (`bridge-agent service`)

Управление системной службой Windows SCM (Service Control Manager) с именем `BridgeLocalAgent`. Требует прав Администратора.

```cmd
:: Установка службы с автоматическим типом запуска
bridge-agent service install

:: Запуск службы
bridge-agent service start

:: Проверка текущего статуса службы
bridge-agent service status

:: Остановка службы
bridge-agent service stop

:: Полное удаление службы из системы
bridge-agent service remove
```

---

### 3.4. Запуск в консольном режиме с интерактивным монитором (`bridge-agent run`)

Запуск демона агента в интерактивном окне (или через пункт `[3]` / `[1]` в `start.bat`).

В этом режиме агент автоматически настраивает кодовую страницу `chcp 65001` (UTF-8) и активирует встроенный **живой монитор событий** прямо в терминале Windows:
* **Записки в реальном времени:** при получении текста или ссылки с Linux они мгновенно отображаются с отметкой времени и автором `[NOTE]`.
* **Передача файлов:** фиксация входящих (`[ВХОДЯЩИЙ]`) и исходящих (`[ИСХОДЯЩИЙ]`) файлов кармана с размером и статусом проверки SHA-256.
* **Дублирование удаленного выполнения:** при запуске команд через `exec` агент отображает команду, PS-директорию, первые строки вывода и реальный код завершения процесса.

Прямо во время работы агента оператор может вводить локальные команды в эту же консоль:
- `status` — вывод аптайма, сетевых метрик, CWD и статистики кармана.
- `notes` — просмотр последних полученных записок.
- `pocket` — просмотр содержимого каталога Карман.
- `reset` / `kill-session` — сброс рабочей папки PowerShell к исходной.
- `cls` / `clear` — очистка экрана и перерисовка шапки.
- `q` / `exit` — чистое завершение сессии и остановка агента.

```cmd
bridge-agent run
```

---

### 3.5. Отправка файлов в Карман (`bridge-agent drop`)

Копирует указанный файл или каталог в локальное хранилище кармана. Встроенный watchdog немедленно фиксирует добавление и передает файл на Linux.

```cmd
:: Отправка файла
bridge-agent drop "C:\Users\User\Documents\report.xlsx"

:: Отправка с отображением системного диалогового окна Windows
bridge-agent drop "archive.zip" --alert

:: Тихий режим без вывода всплывающих окон
bridge-agent drop "data.bin" --quiet
```

---

### 3.6. Управление системным треем (`bridge-agent tray`)

Запускает значок в области уведомлений Windows (System Tray):
```cmd
:: Запуск только интерфейса трея (при уже работающей службе SCM)
bridge-agent tray

:: Запуск трея с одновременным стартом автономного агента в том же процессе
bridge-agent tray --with-agent
```

Возможности контекстного меню трея:
- Просмотр статуса подключения и порта.
- Запуск и остановка службы Windows SCM.
- Быстрое открытие каталога Карман в Проводнике Windows.
- Завершение работы.

---

### 3.7. Интеграция с Проводником Windows

#### `bridge-agent install-context-menu`
Создает записи в системном реестре Windows (`HKCU\Software\Classes\*\shell\BridgeLocalDrop`), добавляя пункт «Отправить в Карман» при правом клике на любых файлах и папках:
```cmd
bridge-agent install-context-menu
```

#### `bridge-agent uninstall-context-menu`
Удаляет пункт из контекстного меню Проводника:
```cmd
bridge-agent uninstall-context-menu
```

#### `bridge-agent generate-reg [output.reg]`
Создает файл реестра `.reg` для ручного импорта или распространения на другие учетные записи:
```cmd
bridge-agent generate-reg "C:\BridgeLocal\menu.reg"
```

## 4. Единый интерактивный мастер запуска (`start.bat`)

Для максимального удобства пользователя в корне дистрибутива поставляется интерактивный командный файл `start.bat`. Он автоматически определяет наличие прав Администратора и предоставляет единое меню управления:

```text
==============================================================================
             BRIDGE LOCAL — ЕДИНЫЙ ЦЕНТР УПРАВЛЕНИЯ (WINDOWS)
==============================================================================
 Режим: [АДМИНИСТРАТОР] — полный доступ к службам, реестру и брандмауэру
------------------------------------------------------------------------------
 Каталог установки: C:\BridgeLocal
 Служба BridgeLocalAgent: [АКТИВНА / RUNNING]
 Брандмауэр порт 9732:   [РАЗРЕШЕН (OK)]
==============================================================================

  [1] БЫСТРЫЙ СТАРТ ПОД КЛЮЧ (Все в 1 клик, Рекомендуется)
      --> Открывает порт 9732 в Брандмауэре (все профили)
      --> Регистрирует пункт «Отправить в Карман» в Проводнике Windows
      --> Запускает агент Bridge Local в интерактивной консоли

  [2] УСТАНОВКА ПОСТОЯННОЙ ФОНОВОЙ СЛУЖБЫ WINDOWS (SCM)
      --> Полная автонастройка + служба работает в фоне без открытых окон

  [3] Запустить агент в консоли (без изменения настроек)
  [4] Мастер настройки сети и кармана (Порт, Токен, Путь к Карману)
  [5] Глобальная настройка Windows (PATH + BRIDGE_CONFIG + C:\BridgeLocal)
  [6] Управление службой Windows SCM (Старт / Стоп / Перезапуск / Статус)
  [7] Настройка Брандмауэра Windows (Открыть порт 9732 TCP)
  [8] Интеграция с Проводником (Контекстное меню «Отправить в Карман»)
  [9] Системный трей Windows и автозагрузка (System Tray)
  [10] Пересобрать автономный исполняемый файл (bridge-agent.exe)
  [11] Полное удаление и очистка (Служба, Меню, Брандмауэр, Автозагрузка)

  [0] Выход
```

## 5. Решение типичных проблем (Troubleshooting)

### 5.1. Кодировка UTF-8 в консоли Windows
При выполнении удаленных скриптов PowerShell вывод консоли должен декодироваться в UTF-8. Агент автоматически настраивает кодовую страницу `chcp 65001`. Если при ручном запуске в CMD наблюдаются искажения кириллических символов:
```cmd
chcp 65001 >nul
```

### 5.2. Требование прав Администратора (UAC)
Установка службы Windows (`service install`), запуск службы (`service start`) и настройка Брандмауэра требуют привилегий Администратора. Если команда завершается ошибкой доступа:
1. Запустите консоль через правый клик -> **«Запуск от имени администратора»**.
2. Либо запустите `start.bat`, который автоматически запросит повышение прав через стандартное окно UAC Windows.

### 5.3. Проверка прослушиваемого сетевого порта
Убедиться, что агент успешно слушает входящие соединения на порту 9732:
```powershell
netstat -ano | findstr 9732
```
В выводе должна присутствовать строка со статусом `LISTENING`:
```text
  TCP    0.0.0.0:9732           0.0.0.0:0              LISTENING       4912
```
