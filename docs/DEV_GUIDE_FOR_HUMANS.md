## Часть 0. Что это вообще такое и зачем оно нужно?

Представь ситуацию:
У тебя на столе стоят два компьютера (или ноутбук и ПК):
1. **Твой основной рабочий Linux** (где ты пишешь код, работаешь в консоли, запускаешь агентов).
2. **Твой второй компьютер на Windows** (где крутятся специфичные программы, игры, тесты, сборки под Windows или тяжелые сервисы).

Раньше, чтобы передать файл или запустить скрипт, приходилось:
- Втыкать флешку.
- Настраивать сложную и тормозную Samba/SMB-сеть, которая отваливается от чиха.
- Кидать файлы самому себе в Telegram или Discord.
- Пересаживаться за вторую клавиатуру, чтобы открыть PowerShell на Windows.

**Bridge_local решает эту проблему раз и навсегда.**
Это легкий, быстрый и неубиваемый мост между Linux и Windows по локальной сети:
- Хочешь скинуть архив на винду? Пишешь в консоли Linux: `bridge-cli send archive.zip` — и он мгновенно падает в папку на Windows.
- Хочешь скопировать ссылку или текст на винду? Пишешь: `bridge-cli note send "https://..."` — и текст уже в записках на Windows.
- Хочешь запустить команду PowerShell на винде, не вставая со стула? Пишешь: `bridge-cli exec "Get-Process"` — и видишь результат в терминале Linux.
- Хочешь красивый интерфейс с кнопками прямо в консоли? Пишешь: `bridge-cli tui` — и управляешь всем через клавиши F1-F6.

При этом система построена не как наколенный скрипт, а как **настоящая модульная платформа**: все пакеты подписаны криптографией HMAC-SHA256, файлы передаются чанками по 64 КБ с проверкой контрольных сумм SHA-256, зависшие процессы PowerShell на винде корректно убиваются по таймауту, а код готов к расширению на 3+ машины в будущем.

## Часть 1. Карта системы: из чего всё состоит

Вся система разделена на три главных кирпича:

```
[ LINUX МАШИНА ]                                [ WINDOWS МАШИНА ]
┌───────────────────────────┐                   ┌───────────────────────────┐
│ bridge_client_linux       │                   │ bridge_agent_win          │
│ (Консоль bridge-cli,      │   TCP Порт 9732   │ (Фоновая служба или окно  │
│  TUI интерфейс,           │──────────────────▶│  PowerShell runner,       │
│  ИИ-агент agy_cli)        │  HMAC-SHA256 Auth │  Папка Pocket, Записки)   │
└─────────────┬─────────────┘                   └─────────────┬─────────────┘
              │                                               │
              └───────────────┐               ┌───────────────┘
                              ▼               ▼
                        ┌───────────────────────────┐
                        │ bridge_core               │
                        │ (Общее сердце платформы:  │
                        │  протокол пакетов, крипта,│
                        │  модели данных, конфиги)  │
                        └───────────────────────────┘
```

1. **`bridge_core` (Сердце):**
   Общая библиотека, которая одинаково работает и на Linux, и на Windows. Она упаковывает сообщения в сетевые пакеты, шифрует подписи HMAC, проверяет таймстампы и делит файлы на кусочки.
2. **`bridge_agent_win` (Агент на Windows):**
   Программа, которая сидит на Windows. Она открывает сетевой порт (по умолчанию `9732`), ждет команд от Linux, запускает PowerShell и сохраняет файлы в папку `pocket/`.
3. **`bridge_client_linux` (Клиент на Linux):**
   Программа `bridge-cli`, которую запускаешь ты на Linux. Она шлет команды на Windows и выводит ответы в красивом виде.

## Часть 2. Настройка конфигурации (bridge.toml) от А до Я

Оба компьютера должны понимать друг друга. Для этого им нужен файл настроек — `bridge.toml`.

### Где должен лежать файл `bridge.toml`?
- **На Linux:** в текущей папке проекта `bridge.toml` ИЛИ в домашнем каталоге: `~/.config/bridge-local/bridge.toml`.
- **На Windows:** в текущей папке программы `bridge.toml` ИЛИ по системному пути: `C:\BridgeLocal\bridge.toml`.

### Готовый шаблон `bridge.toml` с подробным разбором каждой строчки:

```toml
# ==============================================================================
# СЕКЦИЯ 1: ИМЕНА УЗЛОВ (КТО ЕСТЬ КТО)
# ==============================================================================
[node]
# Имя текущего компьютера в сети (любое понятное слово латиницей):
name = "linux-workstation"

# Имя компьютера, с которым общаемся по умолчанию:
target = "windows-agent"

# ==============================================================================
# СЕКЦИЯ 2: СЕТЬ И АДРЕСА
# ==============================================================================
[network]
# На каком адресе агент слушает входящие подключения:
# "0.0.0.0" означает "слушать на всех сетевых картах и Wi-Fi адаптерах".
listen_host = "0.0.0.0"

# IP-АДРЕС ТВОЕЙ WINDOWS-МАШИНЫ В ЛОКАЛЬНОЙ СЕТИ:
# ВАЖНО: Узнай его на Windows, открыв консоль и набрав команду: ipconfig
# Обычно это что-то вроде 192.168.1.50 или 192.168.0.105.
target_host = "192.168.1.100"

# Сетевой TCP-порт (должен быть ОДИНАКОВЫМ на обоих компах):
port = 9732

# Таймаут подключения в секундах (если за 5 сек винда не ответила — ошибка):
connect_timeout = 5.0

# ==============================================================================
# СЕКЦИЯ 3: БЕЗОПАСНОСТЬ И КЛЮЧ-ПАРОЛЬ
# ==============================================================================
[security]
# САМАЯ ВАЖНАЯ СТРОКА! Общий секретный ключ-пароль (PSK).
# Придумай длинную случайную строку.
# ВНИМАНИЕ: На Linux и на Windows эта строка обязана совпадать точь-в-точь!
secret_key = "SuperSecretSharedKeyChangeMeInProduction12345"

# Максимально допустимая разница во времени между компами (в секундах):
# Нужна для защиты от повтора чужих пакетов. Обычно 60 секунд за глаза.
clock_skew_seconds = 60

# ==============================================================================
# СЕКЦИЯ 4: КАРМАН ДЛЯ ФАЙЛОВ (POCKET)
# ==============================================================================
[pocket]
# Папка, куда физически складываются файлы на диске:
# На Windows это может быть "C:\\BridgeLocal\\pocket" или просто "pocket"
# На Linux это может быть "/home/username/BridgePocket" или "pocket"
storage_path = "pocket"

# Размер порции при передаче файла в байтах (65536 = 64 КБ):
chunk_size = 65536

# Максимальный размер файла для пересылки (1073741824 байт = 1 Гигабайт):
max_file_size = 1073741824

# ==============================================================================
# СЕКЦИЯ 5: ЗАПИСКИ (NOTES)
# ==============================================================================
[notes]
# Файл, куда сохраняются текстовые записки и ссылки:
storage_file = "pocket/notes.jsonl"

# Сколько записок максимум хранить в истории:
max_entries = 1000

# ==============================================================================
# СЕКЦИЯ 6: ВЫПОЛНЕНИЕ КОМАНД POWERSHELL
# ==============================================================================
[executor]
# Сколько секунд ждать выполнения команды PowerShell на винде, прежде чем
# принудительно убить зависший процесс:
command_timeout = 30.0

# Кодировка вывода консоли Windows:
encoding = "utf-8"

# ==============================================================================
# СЕКЦИЯ 7: ЛОГИРОВАНИЕ
# ==============================================================================
[logging]
# true = режим разработчика (подробные логи с микросекундами каждого пакета)
# false = чистый боевой режим (только ключевые события)
dev_mode = true

# Куда писать логи:
log_file = "pocket/logs/bridge.jsonl"
```

## Часть 3. Как запустить Windows-агента (два режима)

На Windows агент может работать в двух вариантах:
1. **Простой запуск в консоли (Режим для тестов и разработки).**
2. **Фоновая служба Windows (Режим "поставил и забыл").**

### Вариант 1: Простой консольный запуск (Самый легкий для начала!)

Открываешь терминал (PowerShell или CMD) на Windows и переходишь в папку с проектом:
```powershell
# Если запускаешь из исходников на Python:
python -m bridge_agent_win run

# Или если запускаешь собранный бинарник:
.\dist\bridge-agent.exe run
```

Что произойдет:
- В окне появится сообщение: `Bridge Local Agent listening on 0.0.0.0:9732`.
- Окно остается открытым. Все запросы от Linux будут сразу видны на экране.
- Чтобы остановить — просто нажми `Ctrl + C`.

---

### Вариант 2: Фоновая служба Windows SCM (Производственный режим)

Если ты не хочешь каждый раз руками открывать терминал на винде, запусти скрипт автоматической установки.

1. Открой PowerShell на Windows **от имени Администратора** (правой кнопкой мыши -> "Запуск от имени администратора").
2. Перейди в папку проекта:
   ```powershell
   cd C:\Bridge_Local
   ```
3. Запусти готовый установщик одной строчкой:
   ```powershell
   powershell -ExecutionPolicy Bypass -File .\scripts\install-service.ps1
   ```

**Что этот скрипт делает сам за тебя:**
- Регистрирует службу `BridgeLocalAgent` в системе Windows.
- Настраивает политику автоперезапуска при сбоях.
- Добавляет папку проекта в исключения Windows Defender (чтобы антивирус не тормозил пересылку файлов).
- Отключает тормозящую индексацию поиска Windows Search на папке `pocket`.
- Открывает порт `9732` во встроенном Брандмауэре Windows.
- Сразу запускает службу!

**Как проверить, что служба работает:**
```powershell
sc.exe query BridgeLocalAgent
```
В строке `STATE` должно быть написано: `RUNNING`.

**Как остановить и удалить службу, если больше не нужна:**
```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\uninstall-service.ps1
```

## Часть 4. Как пользоваться с Linux (повседневная шпаргалка)

Теперь садись за свой Linux. Убедись, что в `bridge.toml` прописан IP адрес винды.

### 1. Проверить связь (Жива ли винда?)
```bash
bridge-cli ping
```
*Если всё хорошо, напишет:* `[OK] Pong received from windows-agent (latency: 1.4ms)`.

### 2. Узнать статус и здоровье винды
```bash
bridge-cli status
```
*Покажет красивую табличку:* процессор Windows (CPU %), сколько оперативной памяти свободно, сколько времени система включена (uptime), и жива ли служба.

### 3. Мгновенно отправить файл на Windows
Тебе больше не нужны флешки или мессенджеры. Передавать можно любые файлы (хоть картинки, хоть zip-архивы на гигабайт):
```bash
# Отправить один файл:
bridge-cli send /home/user/Downloads/archive.zip

# Отправить сразу пачку файлов:
bridge-cli send photo1.png photo2.png document.pdf
```
Файл моментально передастся, проверится контрольная сумма SHA-256 и он появится в папке `pocket/` на Windows.

### 4. Отправить ссылку или текстовую заметку на Windows
Нашел интересную ссылку на Linux и хочешь открыть ее на Windows?
```bash
bridge-cli note send "https://github.com/Anhelm01/Bridge_Local"
```

### 5. Посмотреть список заметок
```bash
bridge-cli note list
```
Покажет последние заметки с ID, датой и текстом.

### 6. Выполнить команду на Windows прямо из консоли Linux
Хочешь узнать, какие программы запущены на винде, или создать папку?
```bash
# Посмотреть список запущенных процессов на Windows:
bridge-cli exec "Get-Process"

# Посмотреть содержимое диска C:
bridge-cli exec "Get-ChildItem C:\"

# Узнать IP адреса винды:
bridge-cli exec "ipconfig"
```
Команда выполняется в настоящем PowerShell с кодировкой UTF-8 (русские буквы не ломаются!). Если команда зависнет намертво — наш сторожевой таймер на винде через 30 секунд принудительно убьет зависший процесс и вернет тебе понятную ошибку.

## Часть 5. Интерактивный TUI: графический терминал

Если тебе надоело вводить команды вручную, открой интерактивный дашборд:
```bash
bridge-cli tui
```

Перед тобой откроется полноценный терминальный интерфейс с вкладками:

```
┌────────────────────────────────────────────────────────────────────────┐
│  BRIDGES MASTER [DRAWB RIDG E]                 Status: CONNECTED [OK]  │
├────────────────────────────────────────────────────────────────────────┤
│ [F1: DASH]  [F2: POCKET]  [F3: NOTES]  [F4: EXEC]  [F5: CONFIG]  [F6]  │
├────────────────────────────────────────────────────────────────────────┤
│                                                                        │
│   Windows Agent:   ONLINE (192.168.1.100:9732)                         │
│   CPU Usage:       4.2 %                                               │
│   RAM Available:   11.4 GB / 16.0 GB                                   │
│   Files in Pocket: 14 files (342.1 MB)                                 │
│   Active Notes:    6 unread                                            │
│                                                                        │
│   [⠋] File Sync: Idle. No active transfers.                           │
│                                                                        │
└────────────────────────────────────────────────────────────────────────┘
```

### Управление клавишами в TUI:
- **`F1` / `1`**: Главный экран мониторинга (DASH).
- **`F2` / `2`**: Управление файлами в кармане (POCKET).
- **`F3` / `3`**: Записки и обмен ссылками (NOTES).
- **`F4` / `4`**: Консоль удаленного запуска команд (EXEC).
- **`F5` / `5`**: Просмотр текущей конфигурации (CONFIG).
- **`Tab`**: Переключение фокуса между списками и кнопками.
- **`q` или `Esc`**: Выход из TUI обратно в обычную консоль.

## Часть 6. Режим разработчика (Dev-Mode) и логи

### Как включить режим разработчика?
В файле `bridge.toml` поставь:
```toml
[logging]
dev_mode = true
```

### Что происходит, когда `dev_mode = true`:
1. Включается **гипер-логирование**:
   - Логируется вообще каждый входящий и исходящий байт сетевого сокета.
   - Записываются микросекундные задержки отправки каждого пакета.
   - Фиксируется каждая файловая блокировка и контрольная сумма.
   - Логируются точные PID процессов PowerShell и их аргументы.
2. Логи пишутся в формате JSONL (каждая строка — это готовый JSON-объект) в файл:
   `pocket/logs/YYYY-MM-DD.jsonl` (каждый день создается отдельный файл с датой).

### Как читать логи:
Поскольку это структурированный JSON, его можно читать стандартной утилитой `jq`:
```bash
# Посмотреть последние 10 событий:
tail -n 10 pocket/logs/2026-09-30.jsonl | jq .

# Отфильтровать только ошибки:
grep '"level":"ERROR"' pocket/logs/2026-09-30.jsonl | jq .
```

### Как выключить подробные логи для повседневной работы:
Поставь `dev_mode = false`. Система перейдет в чистый режим: микросекунды и дампы пакетов перестанут засорять диск, будут записываться только важные события уровня `INFO` и `ERROR`.

## Часть 7. Как вести разработку, запускать тесты и проверять код

Если ты вносишь изменения в исходный код платформы:

### 1. Установка окружения (нужен менеджер пакетов `uv`)
```bash
# Установить все зависимости и инструменты разработчика:
uv sync --all-extras
```

### 2. Запуск автотестов
В нашем проекте написано **311 автоматических тестов**, которые проверяют все модули:
```bash
# ВАЖНО: Запускай тесты именно с префиксом LD_PRELOAD="":
LD_PRELOAD="" uv run pytest
```
*Почему нужен `LD_PRELOAD=""`?*
Если в твоей системе работает proxychains или перехватчик сетевых библиотек, он пытается перехватить локальные сокеты loopback `127.0.0.1` и ломает тесты. Префикс `LD_PRELOAD=""` гарантирует, что тесты пойдут напрямую через ядро Linux без помех.

### 3. Проверка качества кода (Линтер и Типизация)
Перед тем как считать фичу готовой, всегда запускай три строгих проверки:
```bash
# 1. Проверка стиля кода и ошибок (ruff):
uv run ruff check .

# 2. Проверка форматирования (ruff format):
uv run ruff format --check .

# 3. Строгая статическая проверка типов (mypy):
uv run mypy
```
Все три команды должны выводить чистый результат без ошибок (0 warnings, 0 errors).

### 4. ВАЖНЕЙШЕЕ ПРАВИЛО GIT: Никаких авто-коммитов!
В файле `AGENTS.md` записано строгое правило проекта:
> **Ни ИИ-агенты, ни скрипты не имеют права делать `git commit` или `git push` самостоятельно без твоего прямого приказа.**
Все изменения всегда лежат в твоей рабочей директории. Только когда ты сам скажешь: "кинь на гит" или "сделай коммит", изменения будут зафиксированы.

## Часть 8. Что делать, если ничего не работает (Диагностика сбоев)

Если команда завершилась с ошибкой, у нее всегда есть числовой код возврата. Вот таблица, что они значат и как починить проблему:

| Код ошибки | Название ошибки | В чем причина? | Как починить? |
|:---:|:---|:---|:---|
| **`2`** | `NETWORK_ERROR` | Клиент на Linux не может достучаться до винды. | 1. Проверь, запущен ли агент на Windows (`sc.exe query BridgeLocalAgent` или окно консоли).<br>2. Проверь IP адрес в `target_host` в `bridge.toml`.<br>3. Проверь, что винда пингуется (`ping 192.168.1.X`).<br>4. Проверь, открыт ли порт 9732 в Брандмауэре Windows. |
| **`3`** | `AUTH_ERROR` | Не подошел пароль или сбились часы. | 1. Открой `bridge.toml` на обоих компьютерах и убедись, что строчка `secret_key = "..."` совпадает буква в букву.<br>2. Проверь время на обоих компьютерах — разница не должна быть больше 60 секунд. |
| **`4`** | `COMMAND_FAILED` | Ошибка в самой команде PowerShell. | Ты передал команду с синтаксической ошибкой (например, опечатка в имени утилиты). Запусти `bridge-cli exec "твой_скрипт" --json` и посмотри поле `"stderr"`. |
| **`5`** | `TIMEOUT` | Команда или передача файла зависла. | Команда выполнялась дольше положенного (по умолчанию 30 секунд). Наш сторожевой таймер убил процесс, чтобы не вешать систему. Если команда действительно тяжелая — увеличь `command_timeout` в секции `[executor]`. |

### Что делать, если Windows Defender блокирует запуск?
Windows иногда с подозрением относится к новым утилитам, открывающим сетевые порты.
Просто запусти от Администратора на Windows команду:
```powershell
Add-MpPreference -ExclusionPath "C:\Bridge_Local"
Add-MpPreference -ExclusionProcess "bridge-agent.exe"
```
Или запусти наш готовый скрипт: `powershell -ExecutionPolicy Bypass -File .\scripts\install-service.ps1`, он делает это автоматически.
