# Справочник конфигурационного файла Bridge Local (bridge.toml)

Данный документ содержит исчерпывающее нормативное описание структуры, секций, параметров по умолчанию и правил разрешения конфигурационного файла `bridge.toml` платформы **Bridge Local**.

---

## 1. Порядок каскадного поиска конфигурации

При запуске любой утилиты платформы (`bridge-cli`, `bridge-agent`, `bridge-local`) поиск и загрузка файла `bridge.toml` осуществляется строго по следующему каскадному алгоритму (`bridge_core.config.BridgeConfig.load`):

1. **Явный ключ командной строки:** Аргумент `--config <path>` (или `-c <path>`). Имеет наивысший приоритет.
2. **Переменная окружения:** Если определена переменная `BRIDGE_CONFIG`, используется указанный в ней абсолютный или относительный путь.
3. **Локальный рабочий каталог (CWD):** Поиск файла `./bridge.toml` в текущей рабочей директории вызова утилиты.
4. **Каталог исполняемого файла:** Поиск файла `bridge.toml` рядом с бинарным исполняемым файлом (`Path(sys.executable).parent / "bridge.toml"`).
5. **Системные каталоги операционной системы:**
   - **В ОС Windows:** `C:\BridgeLocal\bridge.toml`
   - **В ОС Linux:** `~/.config/bridge-local/bridge.toml`
6. **Каталог распаковки PyInstaller:** Временный каталог `sys._MEIPASS / "bridge.toml"` (при работе в упакованном виде).
7. **Встроенные значения по умолчанию (Fallback):** Если конфигурационный файл не обнаружен ни по одному из указанных путей, создается и возвращается экземпляр `BridgeConfig` с безопасными значениями по умолчанию.

## 2. Полный аннотированный пример файла `bridge.toml`

```toml
# ==============================================================================
# СЕКЦИЯ [node]: Идентификация узла в распределенной сети
# ==============================================================================
[node]
# Уникальное техническое имя узла для маршрутизации пакетов (без пробелов):
name = "workstation-linux"

# Понятное отображаемое имя для вывода в TUI и логах:
display_name = "Рабочая станция Linux"

# ==============================================================================
# СЕКЦИЯ [connection]: Сетевые параметры и криптографическая защита
# ==============================================================================
[connection]
# Для Linux-клиента: IP-адрес или hostname удаленного Windows-агента.
# Для Windows-агента: bind-адрес для прослушивания сокета (0.0.0.0 — все интерфейсы).
host = "192.168.1.150"

# Сетевой TCP-порт (1024..65535, по умолчанию 9732; 0 = динамический порт ОС):
port = 9732

# Таймаут установки соединения и первичного рукопожатия в секундах:
timeout_sec = 5.0

# Секретный токен PSK (Pre-Shared Key) для взаимной аутентификации и HMAC-SHA256:
# Должен быть посимвольно идентичным на стороне клиента и агента.
# Если указана пустая строка или параметр отсутствует, аутентификация отключена.
psk_token = "4a8c9b2f1e0d3a567890bcdef1234567890abcdef1234567890abcdef1234567"

# Опциональные пути к TLS-сертификатам (для сокетов с прямым шифрованием TLS):
# tls_cert_path = "/etc/bridge-local/cert.pem"
# tls_key_path = "/etc/bridge-local/key.pem"

# ==============================================================================
# СЕКЦИЯ [heartbeat]: Мониторинг жизнеспособности узла (Fail-Fast Liveness)
# ==============================================================================
[heartbeat]
# Интервал отправки периодических фоновых зондов Ping в секундах:
interval_sec = 2.0

# Жесткий таймаут ожидания ответа Pong в секундах (порог Fail-Fast):
timeout_sec = 1.5

# Количество последовательно пропущенных ответов до маркировки узла как UNREACHABLE:
max_missed = 3

# Пауза перед попыткой повторного установления связи в секундах:
reconnect_delay_sec = 5.0

# ==============================================================================
# СЕКЦИЯ [pocket]: Хранилище файлов общего кармана
# ==============================================================================
[pocket]
# Локальный путь к общему каталогу кармана на диске:
# Относительный путь разрешается относительно расположения самого файла bridge.toml.
path = "./pocket"

# Имя подкаталога для сохранения файлов ежедневного аудита:
logs_subdir = "logs"

# Включение автоматического отслеживания изменений файлов через watchdog:
sync_watch = true

# Максимальный размер блока (чанка) при потоковой передаче файлов в байтах (64 КБ):
# Диапазон допустимых значений: от 1 байта до 4 194 304 байт (4 МБ).
max_chunk_size = 65536

# Срок автоматической ротации и хранения файлов аудита в днях:
log_max_days = 30

# ==============================================================================
# СЕКЦИЯ [exec]: Удаленное выполнение команд PowerShell
# ==============================================================================
[exec]
# Таймаут выполнения команды по умолчанию в секундах (диапазон 1..3600):
default_timeout_sec = 30

# Запуск команд PowerShell с повышенными привилегиями по умолчанию:
run_as_admin = true

# Принудительная установка кодировки UTF-8 в среде исполнения (chcp 65001):
force_utf8 = true

# ==============================================================================
# СЕКЦИЯ [logging]: Управление логированием и режимами трассировки
# ==============================================================================
[logging]
# Порог фильтрации системных сообщений: TRACE, DEBUG, INFO, WARNING, ERROR:
level = "TRACE"

# Режим разработчика (Dev-Mode Hyper-Logging):
# true  — детальная микросекундная трассировка сетевых пакетов, блокировок и дескрипторов.
# false — чистый релизный режим без микросекунд и номеров строк кода.
dev_mode = true

# Вывод диагностических сообщений в терминал (stdout/stderr):
console_output = true

# Опциональный путь к файлу для записи логов (None — только консоль и аудит):
# file_output = "/var/log/bridge-local.log"
```

## 3. Таблица всех секций и параметров конфигурации

| Секция | Имя параметра | Тип | По умолчанию | Описание и валидация |
|:---|:---|:---|:---|:---|
| **`[node]`** | `name` | `str` | `"local-node"` | Уникальное имя узла для маршрутизации пакетов. |
| | `display_name` | `str \| None` | `None` | Человекочитаемое имя узла для отображения в интерфейсе. |
| **`[connection]`** | `host` | `str` | `"0.0.0.0"` | IP-адрес или hostname целевого узла (клиент) / интерфейс прослушивания (агент). |
| | `port` | `int` | `9732` | Сетевой порт TCP (`0` — динамический порт ОС, либо `1024..65535`). |
| | `timeout_sec` | `float` | `5.0` | Таймаут первичного сетевого подключения в секундах (> 0). |
| | `psk_token` | `str \| None` | `None` | Секретный общий ключ PSK для взаимной аутентификации HMAC-SHA256. |
| | `tls_cert_path`| `str \| None` | `None` | Путь к публичному TLS-сертификату формата PEM. |
| | `tls_key_path` | `str \| None` | `None` | Путь к приватному ключу TLS формата PEM. |
| **`[heartbeat]`** | `interval_sec` | `float` | `2.0` | Периодичность отправки фоновых зондов Ping в секундах (> 0). |
| | `timeout_sec` | `float` | `1.5` | Таймаут ожидания ответа Pong в секундах (> 0, Fail-Fast). |
| | `max_missed` | `int` | `3` | Допустимое число пропущенных зондов до смены статуса на `UNREACHABLE` (>= 1). |
| | `reconnect_delay_sec` | `float` | `5.0` | Интервал ожидания перед повторной попыткой переподключения (> 0). |
| **`[pocket]`** | `path` | `str` | `"./pocket"` | Локальный каталог хранения синхронизируемых файлов кармана. |
| | `logs_subdir` | `str` | `"logs"` | Имя вложенного каталога для сохранения файлов ежедневного аудита. |
| | `sync_watch` | `bool` | `true` | Использование файлового наблюдателя `watchdog` для автоматического обнаружения файлов. |
| | `max_chunk_size`| `int` | `65536` | Максимальный размер чанка при передаче файлов в байтах (`1..4194304`). |
| | `log_max_days`| `int` | `30` | Количество дней хранения файлов аудита до их удаления (>= 1). |
| **`[exec]`** | `default_timeout_sec` | `int` | `30` | Лимит времени выполнения команды PowerShell в секундах (`1..3600`). |
| | `run_as_admin`| `bool` | `true` | Флаг запуска процессов PowerShell с повышенными привилегиями. |
| | `force_utf8` | `bool` | `true` | Принудительная инициализация кодировки UTF-8 в дочернем процессе. |
| **`[logging]`** | `level` | `str` | `"TRACE"` | Порог фильтрации сообщений лога (`TRACE`, `DEBUG`, `INFO`, `WARNING`, `ERROR`). |
| | `dev_mode` | `bool` | `true` | Режим расширенной dev-трассировки всех уровней протокола. |
| | `console_output` | `bool` | `true` | Вывод логов в консольные потоки вывода. |
| | `file_output` | `str \| None` | `None` | Путь к выделенному файлу журнала (None — только аудит и консоль). |

## 4. Разрешение относительных путей

1. Если в параметре `pocket.path` указан относительный путь (например, `./pocket` или `data/pocket`), он разрешается относительно **каталога размещения загруженного файла `bridge.toml`**, а не текущей рабочей директории терминала.
2. Это гарантирует стабильность работы фоновых служб (в том числе Windows SCM Service и systemd), запускаемых из системных каталогов (`System32`).

## 5. Типовые профили конфигурации

### Профиль 5.1. Разработка и тестирование (Dev / Debug)
```toml
[node]
name = "dev-workstation"

[connection]
host = "127.0.0.1"
port = 9732
psk_token = "dev_secret_token_123"

[logging]
level = "TRACE"
dev_mode = true
console_output = true
```

### Профиль 5.2. Промышленная эксплуатация (Production)
```toml
[node]
name = "prod-node-linux"

[connection]
host = "192.168.1.150"
port = 9732
timeout_sec = 3.0
psk_token = "9f82c41870...prod_key"

[heartbeat]
interval_sec = 3.0
timeout_sec = 1.0
max_missed = 2

[exec]
default_timeout_sec = 60

[logging]
level = "INFO"
dev_mode = false
console_output = false
file_output = "/var/log/bridge-local.log"
```
