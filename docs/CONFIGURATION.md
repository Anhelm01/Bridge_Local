# Справочник по конфигурации Bridge_local (bridge.toml)

Данный документ содержит исчерпывающее описание структуры, секций, параметров по умолчанию и правил валидации конфигурационного файла `bridge.toml` платформы **Bridge_local**.

---

## 1. Порядок и каскад обнаружения конфигурации

При запуске любого компонента (`bridge-cli`, `bridge-agent`, `bridge-local`) поиск файла `bridge.toml` выполняется строго по следующему каскадному алгоритму:

1. **Явный флаг командной строки:** Аргумент `--config <path>` (имеет наивысший приоритет).
2. **Переменная окружения:** Если установлена переменная `BRIDGE_CONFIG`, используется указанный в ней путь.
3. **Текущий рабочий каталог (CWD):** Поиск файла `./bridge.toml` в текущей директории запуска.
4. **Каталог исполняемого файла:** Поиск файла `bridge.toml` в каталоге рядом с бинарником (`Path(sys.executable).parent / "bridge.toml"`).
5. **Системный путь платформы:**
   - **Windows:** `C:\BridgeLocal\bridge.toml`
   - **Linux:** `~/.config/bridge-local/bridge.toml`
6. **Значения по умолчанию (Fallback):** Если файл не найден ни по одному из путей, применяются безопасные встроенные значения по умолчанию с фиксацией информационного сообщения в логе.

## 2. Полный аннотированный файл `bridge.toml`

```toml
# ==============================================================================
# СЕКЦИЯ [node]: Идентификация узла
# ==============================================================================
[node]
# Уникальное имя текущего узла (ASCII строка без пробелов):
name = "workstation-linux"

# Человекочитаемое отображаемое имя для отображения в TUI и логах:
display_name = "Основная рабочая станция Linux"

# ==============================================================================
# СЕКЦИЯ [connection]: Сетевое подключение и криптография
# ==============================================================================
[connection]
# Для клиента (Linux): IP-адрес или hostname целевого Windows-агента.
# Для агента (Windows): адрес для прослушивания (0.0.0.0 — все сетевые интерфейсы).
host = "192.168.1.100"

# Сетевой TCP-порт (диапазон 1024..65535, по умолчанию 9732):
port = 9732

# Таймаут установки TCP-соединения в секундах:
timeout_sec = 5.0

# Pre-Shared Key (PSK) токен для взаимной аутентификации и HMAC-SHA256 подписи:
# Должен быть идентичным на стороне клиента и агента.
psk_token = "A1f849c2d8e3b4a56c7d8e9f0123456789abcdef0123456789abcdef01234567"

# Опциональные пути к TLS сертификатам (для режима прямого шифрования сокета):
# tls_cert_path = "/etc/bridge-local/cert.pem"
# tls_key_path = "/etc/bridge-local/key.pem"

# ==============================================================================
# СЕКЦИЯ [heartbeat]: Мониторинг доступности и Fail-Fast Liveness
# ==============================================================================
[heartbeat]
# Периодичность отправки фоновых зондов ping в секундах:
interval_sec = 2.0

# Жесткий таймаут ожидания ответа pong в секундах (Fail-Fast):
timeout_sec = 1.5

# Количество последовательно пропущенных ответов до маркировки UNREACHABLE:
max_missed = 3

# Задержка перед повторной попыткой восстановления соединения в секундах:
reconnect_delay_sec = 5.0

# ==============================================================================
# СЕКЦИЯ [pocket]: Каталог передачи файлов «Карман»
# ==============================================================================
[pocket]
# Локальный путь к общей директории кармана на диске:
# Windows пример: "C:\\BridgeLocal\\pocket"
# Linux пример: "~/BridgePocket" или "./pocket"
path = "./pocket"

# Имя вложенного подкаталога для хранения ежедневных файлов аудита:
logs_subdir = "logs"

# Автоматическое отслеживание изменений файловой системы через watchdog:
sync_watch = true

# Размер передаваемого блока файла (чанка) в байтах (по умолчанию 64 КБ):
# Максимально допустимо: 4194304 (4 МБ).
max_chunk_size = 65536

# Ротация логов: автоматическое удаление лог-файлов старше N дней:
log_max_days = 30

# ==============================================================================
# СЕКЦИЯ [exec]: Удаленное выполнение команд PowerShell
# ==============================================================================
[exec]
# Таймаут выполнения скрипта по умолчанию в секундах (1..3600):
default_timeout_sec = 30

# Запуск с повышенными привилегиями по умолчанию:
run_as_admin = true

# Принудительная установка кодировки UTF-8 в дочернем процессе (chcp 65001):
force_utf8 = true

# ==============================================================================
# СЕКЦИЯ [logging]: Управление логированием
# ==============================================================================
[logging]
# Минимальный уровень логирования: TRACE, DEBUG, INFO, WARNING, ERROR:
level = "INFO"

# Флаг режима разработчика:
# true  — подробная микросекундная трассировка сетевых фреймов и блокировок.
# false — чистый релизный режим (без микросекунд и сырых дампов пакетов).
dev_mode = false

# Вывод логов в консоль (stdout/stderr):
console_output = true

# Запись логов в отдельный файл (None — запись только в консоль и ежедневный аудит):
# file_output = "/var/log/bridge-local.log"
```

## 3. Таблица параметров конфигурации

| Секция | Параметр | Тип | По умолчанию | Описание |

| **`[connection]`** | `host` | `str` | `"0.0.0.0"` | IP-адрес агента или bind-адрес. |
| | `port` | `int` | `9732` | TCP-порт (1024..65535). |
| | `timeout_sec` | `float` | `5.0` | Таймаут соединения в секундах. |
| | `psk_token` | `str \| None` | `None` | Секретный ключ взаимной аутентификации. |
| | `tls_cert_path`| `str \| None` | `None` | Путь к публичному TLS сертификату. |
| | `tls_key_path` | `str \| None` | `None` | Путь к приватному ключу TLS. |
| **`[heartbeat]`** | `interval_sec` | `float` | `2.0` | Интервал опроса liveness-зондом. |
| | `timeout_sec` | `float` | `1.5` | Таймаут ожидания liveness-ответа. |
| | `max_missed` | `int` | `3` | Допустимое число пропусков зонда. |
| | `reconnect_delay_sec` | `float` | `5.0` | Пауза перед переподключением. |
| **`[pocket]`** | `path` | `str` | `"./pocket"` | Локальный каталог кармана. |
| | `logs_subdir` | `str` | `"logs"` | Каталог аудит-логов внутри кармана. |
| | `sync_watch` | `bool` | `true` | Использовать файловый вотчер watchdog. |
| | `max_chunk_size`| `int` | `65536` | Размер чанка (байт) при пересылке. |
| | `log_max_days`| `int` | `30` | Срок хранения логов в днях. |
| **`[exec]`** | `default_timeout_sec`| `int`| `30` | Таймаут команды PowerShell (сек). |
| | `run_as_admin`| `bool` | `true` | Запуск команд от имени Администратора. |
| | `force_utf8` | `bool` | `true` | Принудительная кодировка UTF-8. |

| | `dev_mode` | `bool` | `true` | Режим расширенной dev-трассировки. |

| | `file_output` | `str \| None`| `None` | Опциональный отдельный файл лога. |

## 4. Переменные окружения

Для переопределения параметров в контейнерах и сценариях CI/CD поддерживаются следующие переменные:

- `BRIDGE_CONFIG` — Абсолютный путь к альтернативному файлу `bridge.toml`.
- `BRIDGE_NODE_NAME` — Переопределение имени узла (`node.name`).
- `BRIDGE_TARGET_HOST` — Переопределение IP-адреса агента (`connection.host`).
- `BRIDGE_PORT` — Переопределение TCP-порта (`connection.port`).
- `BRIDGE_PSK_TOKEN` — Переопределение общего секретного ключа (`connection.psk_token`).
- `BRIDGE_DEV_MODE` — Принудительное включение/отключение dev-режима (`1`/`0`).

## 5. Рекомендации по настройке профилей

### Профиль «Разработка и отладка» (Dev Profile)
```toml
[logging]
level = "TRACE"
dev_mode = true
console_output = true

[exec]
default_timeout_sec = 60
```

### Профиль «Промышленная эксплуатация» (Production Profile)
```toml
[logging]
level = "INFO"
dev_mode = false
console_output = false
file_output = "/var/log/bridge-local.log"

[connection]
timeout_sec = 3.0

[exec]
default_timeout_sec = 30
```
